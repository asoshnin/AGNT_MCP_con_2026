# Sandboxing My AI Agent, One Layer at a Time

**Canonical Presentation on Sched:** [Sandboxing My AI Agent, One Layer at a Time](https://agntconmcpconeu26.sched.com/event/2RB98/sandboxing-my-ai-agent-one-layer-at-a-time-juan-antonio-osorio-stacklok-inc)  
**Speakers:** Juan A. Osorio (Principal Engineer, Stacklok Inc.)  
**Relevance Score:** `0.95`

## Essence

This talk addresses the critical security challenge of running AI agents that generate and execute code from untrusted inputs. The core insight is that while hardware-isolated microVMs (like those leveraging libkrun/KVM) provide a foundational layer of isolation, they are insufficient on their own. The speaker advocates for a multi-layered defense-in-depth strategy, progressively adding protections such as copy-on-write workspace snapshots with review gates, non-overridable secret exclusions, DNS-aware egress firewalls, and hardened guest environments (e.g., Wolfi with custom PID 1, seccomp). This comprehensive approach extends to securing the security tools' configurations themselves, emphasizing that isolation is merely the starting point for robust AI agent security.

## Key Takeaways & Recommendations

- Utilize hardware-isolated microVMs (e.g., libkrun/KVM) as the foundational layer for agent execution to ensure strong kernel-level separation.
- Implement copy-on-write workspace snapshots with a per-file review gate to control agent access and modifications to the environment.
- Deploy a DNS-aware egress firewall to prevent unauthorized data exfiltration by AI agents.
- Harden guest environments with minimal OS images (e.g., Wolfi), custom PID 1, dropped capabilities, and seccomp profiles to reduce attack surface.
